Create, update, list, reload and remove nikcli plugins and mods (hooks that block, rewrite, approve or draw) — the way nikcli extends itself.

Use this when the user asks nikcli to gain a new capability that should outlive the session: "create a plugin that sends me desktop notifications", "add a tool that queries our Jira", "log every bash command to a file". The plugin is written to its own folder, its dependencies are installed, and nikcli hot-reloads it immediately — no restart. Its hooks run from then on and any tools it defines are callable from your next step.

Actions:
- create: write a new plugin. Requires `name`, `source`; `description`, `dependencies`, `scope` optional. Fails if the plugin already exists.
- update: replace an existing plugin's `source` (and optionally `description`/`dependencies`). Use it to fix a plugin that failed to load.
- list: every configured plugin with the hooks and tools it registered, or its load error.
- reload: re-read plugins from disk (after editing a plugin's files with other tools).
- remove: delete a plugin folder created here and unload it.

Layout: `<config>/plugins/<name>/index.ts` + `package.json`, where `<config>` is `~/.config/nikcli` for scope "global" (default: every project on this machine) or the project's `.nikcli/` for scope "project". Read the files with the read tool when you need to change a plugin incrementally.

Writing `source` (TypeScript, ESM, runs inside nikcli on Bun — Bun APIs and Node built-ins are available):

```ts
import type { Plugin } from "@nikcli-ai/plugin"
import { tool } from "@nikcli-ai/plugin" // only if you define tools

export const MyPlugin: Plugin = async ({ client, project, directory, worktree, serverUrl, $ }) => {
  // one-time setup; `$` is Bun's shell: await $`osascript -e ${script}`.quiet()
  return {
    event: async ({ event }) => {
      if (event.type === "session.idle") { /* event.properties.sessionID */ }
    },
    tool: {
      my_tool: tool({
        description: "What the tool does",
        args: { query: tool.schema.string().describe("…") }, // tool.schema is zod
        async execute(args, ctx) { return `result for ${args.query}` }, // string or { title, output, metadata }
      }),
    },
    dispose: async () => { /* clear timers, close sockets, unsubscribe */ },
  }
}
```

Every exported function is initialised as a plugin, so export only plugin functions. Hooks available on the returned object:
- `event({ event })` — every bus event. Useful types: `session.idle`, `session.status` (properties.status.type busy|idle|retry), `session.error`, `permission.asked`, `question.asked`, `message.updated`, `message.part.updated`, `file.edited`, `todo.updated`, `session.created`.
- `config(config)` — the resolved nikcli config, on load and after config changes.
- `tool` — tools the agent can call, keyed by tool id.
- `"tool.execute.before"(input, output)` / `"tool.execute.after"(input, output)` — observe or rewrite tool calls (`output.args` before, `output.output` after).
- `"shell.env"(input, output)` — add env vars to shells (`output.env`).
- `"chat.params"`, `"chat.message"`, `"command.execute.before"`, `"experimental.chat.system.transform"` (push to `output.system`), `"experimental.session.compacting"`.
- To approve, refuse or block tool calls and permission checks, write a mod (below), not a hook: v1 hooks can only rewrite arguments and results, they cannot stop a call.
- `dispose()` — called before the plugin is reloaded or removed. Anything long-lived you start (setInterval, servers, watchers, child processes) MUST be released here, or a reload will leave duplicates running.

Mods — the way to intercept and change how nikcli works. A mod is a plugin whose module exports `register(on, options)` instead of a plugin function. Use a mod when the user wants to block, rewrite, approve or replace something: refuse risky commands, rewrite prompts, redact secrets from tool output, ask before a dangerous call, change a tool's description.

```ts
export function register(on) {
  // Refuse force pushes. The matcher limits the hook to bash calls, so e.command is the shell command.
  on("tool.call", { tool: "bash" }, async ($, e, next) => {
    if (/git push .*--force/.test(e.command)) return { deny: "Force pushes are not allowed here. Push to a new branch." }
    return next(e) // pass the event on unchanged
  })
}
```

Each hook is `async ($, e, next)`: `$` is the mods API, `e` the event (deeply frozen: pass a changed copy to `next`), `next` the rest of the chain. A hook can observe (`return next(e)`), rewrite (`return next({ ...e, text: e.text.trim() })`), answer without calling `next` (return a result), or wrap (`const result = await next(e)`, then return a changed result). A hook that throws, or runs over 10 s of its own time, is skipped; add `.catch(async ($, e, next) => ({ deny: "guard failed" }))` after `on(...)` to fail closed.

Events: `tool.call` (e.tool plus the tool's arguments as fields, `e.command` for bash; answer `{ deny: reason }` or `{ result }`, or `next(e)`; retry by calling `next(e)` again when `result.isError`), `tool.check` (e.rule is what the permission rules decided; answer `{ decision: "allow" | "ask" | "deny", reason }` before the user is asked — a deny rule always stays a deny), `tool.describe` (answer `{ description }`), `prompt.submit` (rewrite `text`, add `context` lines only the model reads, or answer `{ drop: reason }`), `prompt.section` (e.name is agent|provider|system|user; answer `{ text }` or `{ text: null }` to omit) and `prompt.compose` (answer `{ sections }`), `command.run` (rewrite `arguments` or answer `{ text }` with no model turn), `turn.start`, `turn.step` (pass `next({ ...e, model: "provider/model" })` to send the request to another model), `turn.complete`, `agent.offer` (answer `{ isOffered: false }`), `agent.spawn` (answer `{ deny }` or pass a changed `model`), `skill.prompt` (answer `{ text }`), `session.compact` (answer `{ skip: reason }`), `command.describe` (pass a changed `description`, `argumentHint` or `isHidden`), `session.start`, `session.end`. Matchers: `on("tool.call", { tool: ["edit", "write"] }, hook)` or a RegExp.

Drawing: answer `ui.render` for `{ component: "AbovePrompt" }` (the band above the prompt) or `{ component: "Pane", requestId: id }` (a pane opened with `$.ui.open({ id, title, placement: "dock" | "inline" })`) with `{ tree }` built from `const { Box, Text, Button, Input, Select, Markdown, Code, Link } = $.ui.resolve(e)`; a `Button({ key, label })` press arrives as a `ui.press { key }` hook that answers `{ handled: true }`, typing as `ui.input { key, value, submit }`, a choice as `ui.select`. Sites nikcli draws itself can be replaced the same way: `ToolUse` (props tool, status, input, output; requestId is the call id), `UserMessage` and `AssistantMessage` (props text; requestId is the message id), `Spinner` (rewrite `props.word`). Call `$.ui.invalidate()` to draw again.

`$` offers `$.fs`, `$.process.run([cmd, ...args])`, `$.http.fetch`, `$.env`, `$.store`, `$.clock`, `$.ui` (log, toast, ask, resolve, invalidate, open, close, panes), `$.command.register`, `$.tool.register`, `$.session` (id, cwd, root, messages, model, turns, repo, version, usage), `$.prompt.submit/fill`, `$.turn.abort`, `$.model.complete/classify`, `$.settings.read`, `$.mcp.call/connect`, `$.agent.list`. Write each call in full, `$.fs.read(...)`: a module that reaches `$` through an alias, a destructuring or a computed key is refused, because it cannot be reviewed. Calls nikcli does not have yet throw "is not available in nikcli yet"; `nikcli mod validate <dir>` lists them. Mods run with the user's permissions and are not sandboxed; organization policy (`mod` in managed settings) can refuse them and `sec-default` keeps deny rules in force.

Rules:
- `name` is kebab-case and becomes the folder name; tool ids should be snake_case and prefixed with the plugin's purpose to avoid collisions.
- Put npm packages in `dependencies` (e.g. {"node-notifier": "^10.0.1"}); prefer built-ins and OS commands when they suffice.
- Never swallow the whole plugin in try/catch silently; log with `console.error` sparingly — stdout/stderr are shared with the TUI.
- The result tells you whether the plugin loaded and what it registered. If it failed, read the error, fix the source and call `update`. Do not report success to the user until the result says the plugin is loaded.
