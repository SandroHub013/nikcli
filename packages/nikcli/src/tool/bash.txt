Execute a shell command. Running on ${platform}; commands are interpreted by ${shell}, so use that shell's syntax. The working directory is in <env>.

- Short, bounded commands only (git, package managers, builds, one-shot scripts); long-running ones (dev servers, watchers, test suites, streaming installs) go to `monitor`.
- Read files with the read tool and change them with the edit tools, not with cat/sed/echo. For searching, a single `rg`/`find`/`ls` is fine when it saves calls.
- Prefer `workdir` over `cd path && …`. Quote paths with spaces. Use the project's package manager (from the lockfile).
- Optional `timeout` ms (default 120000). Output truncates at ${maxLines} lines / ${maxBytes} bytes (full log on disk).
- Describe the command in 5–10 words in the description field.
- Never skip git hooks (`--no-verify`) or force-push to main/master unless asked. Do not commit unless the user asks.
